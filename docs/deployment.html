Deploy Chomp Sandwich to the internet

No prior deployment experience needed. Follow each step in order and copy-paste the commands. Everything here uses free services.

iWhat you'll build

By the end of this guide your sandwich-ordering website will be live on a real web address, backed by a real database, able to send login codes by SMS — all without paying anything. Here is the big picture:

Vercel

Runs your website & gives it a web address.

Neon

Free PostgreSQL database that stores users, orders, etc.

Kavenegar

Sends the 6-digit login codes by SMS.

GitHub

Stores your code; Vercel deploys from it.

How long? About 30–45 minutes the first time. You only do steps 1–7 once.

iiTools you'll need (install once)

  1. Node.js (version 18 or newer) — nodejs.org. Pick the "LTS" button.
  2. Git — git-scm.com/downloads.
  3. A free GitHub account — github.com/signup.
  4. A code editor like VS Code (you likely already have it).

Check they installed correctly

Open a terminal (on Windows: search "Git Bash" or use VS Code's terminal) and run: 

node -v
git --version

If each prints a version number (e.g. v20.11.0), you're ready.

0Run it on your computer first

Always get it working locally before going live. In the project folder, run: 

# install all the project's building blocks
npm install

# copy the example settings file to a real one
cp .env.example .env
Good news: the project ships with OTP_DEV_MODE="1", so during local testing the login code is printed in your terminal instead of needing real SMS.

You need a database even locally. The easiest path is to skip local Postgres and point .env at your free Neon database (created in step 1). Once DATABASE_URL is set, run: 

npm run db:push     # create the tables
npm run db:seed     # add the menu + an admin account
npm run dev         # start the site

Open http://localhost:3000. 🎉

1Create a free database (Neon)

1

Sign up

Go to neon.tech and sign in with GitHub. It's free.

2

Create a project

Click New Project. Pick a region close to your users (e.g. Frankfurt for Iran/Europe). Name it chomp.

3

Copy the connection string

Neon shows a Connection string that starts with postgresql://. Click Copy. It looks like: 

postgresql://user:password@ep-cool-name.eu-central-1.aws.neon.tech/neondb?sslmode=require

Paste it into your .env file as the value of DATABASE_URL (keep the quotes).

Keep it secret. This string is a password to your database. Never share it or commit it to GitHub. (Our .gitignore already protects .env.)

2Set up SMS login codes (Kavenegar)

This powers the "send me a code" login. You can do this now or later — until you add a key, codes print to the server log.

1

Make an account

Sign up at panel.kavenegar.com.

2

Get your API key

In the panel, find your API Key and copy it. Put it in .env as KAVENEGAR_API_KEY.

3

Create an OTP template

Create a Verify Lookup template named chomp-otp with a %token placeholder, e.g. "Your Chomp code is %token". Put the name in KAVENEGAR_OTP_TEMPLATE.

When you're ready to send real SMS, set OTP_DEV_MODE="0".

3Put your code on GitHub

Vercel deploys straight from GitHub. If your project isn't on GitHub yet: 

git init
git add .
git commit -m "Chomp Sandwich"
# create an EMPTY repo at github.com/new, then:
git branch -M main
git remote add origin https://github.com/YOUR_NAME/chomp.git
git push -u origin main
Before pushing, confirm .env is NOT included. Run git status — you should not see .env listed. (It's already ignored.)

4Deploy to Vercel

1

Sign in

Go to vercel.com and log in with GitHub.

2

Import the project

Click Add New → Project, choose your chomp repository, and click Import.

3

Don't click Deploy yet

First open the Environment Variables section (next step). Vercel auto-detects Next.js — no build settings to change.

5Add your environment variables

In Vercel's Environment Variables box, add each of these (Name + Value), then deploy:

Name What to put
DATABASE_URL Your Neon connection string
AUTH_SECRET A long random string (generate below)
AUTH_URL Your site URL, e.g. https://chomp.vercel.app
KAVENEGAR_API_KEY From Kavenegar (or leave blank for now)
KAVENEGAR_OTP_TEMPLATE chomp-otp
OTP_DEV_MODE 1 to print codes, 0 for real SMS
ADMIN_PHONE Your phone, e.g. 09120000000
ADMIN_PASSWORD A strong admin password

Generate a secure AUTH_SECRET

npx auth secret
# or:
openssl rand -base64 32

Now click Deploy and wait for the build to finish (~2 minutes). You'll get a live URL.

Set AUTH_URL after the first deploy: once you know your real URL, update AUTH_URL to match and redeploy (step 9).

6Create the database tables

The database is empty until we create the tables. Run this from your computer (it talks to Neon over the internet): 

# make sure .env points at your NEON database, then:
npm run db:deploy   # applies migrations
# first time only, if you have no migrations yet:
npm run db:push     # creates tables directly from the schema
What's the difference? db:push is the quick way for your first launch. db:migrate/db:deploy keep a versioned history — better once you have real data.

7Add the menu & your admin account 

npm run db:seed

This fills the menu (sandwiches, ingredients, tags) and creates an admin using the ADMIN_PHONE / ADMIN_PASSWORD you set. Log in with those to reach /admin.

8Test everything works

  • ✓ Visit your site URL — the menu loads.
  • ✓ Click the account icon → enter a phone → you get the password or code step.
  • ✓ With OTP_DEV_MODE=1, the code appears in Vercel's Logs tab.
  • ✓ Log in as admin → /admin opens. A normal user is redirected away.
  • ✓ Protected pages bounce you to /login when signed out; /menu stays public.

9Updating your site later

Every time you push to GitHub, Vercel rebuilds and redeploys automatically: 

git add .
git commit -m "describe your change"
git push

If you changed the database structure (the Prisma schema), also run: 

npm run db:migrate   # locally, creates a migration
git add . && git commit -m "db changes" && git push
# Vercel runs `prisma generate` automatically during build.
# Apply migrations to prod once:
npm run db:deploy

!Troubleshooting

"Can't reach database server"

Your DATABASE_URL is wrong or missing ?sslmode=require. Re-copy it from Neon.

Login always fails

Check AUTH_SECRET and AUTH_URL are set in Vercel and that AUTH_URL exactly matches your site URL (no trailing slash).

No SMS arrives

If OTP_DEV_MODE=1 the code only prints to the Logs. For real SMS set it to 0 and confirm your Kavenegar key + template name.

Build fails on Vercel

Open the build log. Most often a missing environment variable. Add it and redeploy.

Admin page redirects me home

That account isn't an admin. Log in with ADMIN_PHONE, or re-run npm run db:seed.

?Plain-English glossary

Term Means
Environment variable A secret setting (like a password) given to the app without writing it in the code.
Database Where your users, orders, and menu are permanently stored.
Migration A recorded change to the database structure.
Seed Filling an empty database with starter data (the menu + admin).
OTP One-Time Password — the 6-digit code sent by SMS to log in.
Deploy Publishing your site so the public can visit it.
