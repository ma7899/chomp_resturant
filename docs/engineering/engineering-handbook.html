How to Read the Codebase

روش خواندن کدبیس

  1. Start with app/layout and route pages.
  2. Follow each page to server actions or API routes.
  3. Trace business logic in lib/server and validation in lib/validation.
  4. Review shared state in Zustand stores.
  1. از app/layout و صفحات شروع کنید.
  2. هر صفحه را تا server action یا API route دنبال کنید.
  3. منطق دامنه را در lib/server و validation را در lib/validation ببینید.
  4. استیت مشترک را در Zustand مرور کنید.

Database Migration Roadmap (When Needed)

نقشه راه مهاجرت دیتابیس (در صورت نیاز)

Safe 6-Step Migration Path

مسیر امن 6 مرحله‌ای مهاجرت

  1. Add schema changes in Prisma with backward compatibility.
  2. Create migration and apply in staging.
  3. Deploy app code that can read old/new shapes.
  4. Run data backfill script if required.
  5. Switch writes fully to new schema.
  6. Remove legacy fields/tables in a later release.
  1. تغییر schema را با سازگاری عقب‌رو در Prisma اضافه کنید.
  2. migration بسازید و روی staging اعمال کنید.
  3. کدی deploy کنید که هم فرم قدیم هم جدید را بخواند.
  4. در صورت نیاز backfill اجرا کنید.
  5. نوشتن داده را کامل به schema جدید منتقل کنید.
  6. فیلد/جدول Legacy را در release بعدی حذف کنید.

Operational Migration Matrix

ماتریس عملیاتی مهاجرت

Phase Action Guardrail Rollback
Expand Add nullable columns / new tables No breaking constraints Revert code only
Migrate Backfill and dual-read Validation and row counts Disable new readers
Switch Flip writes to new model Canary + metrics Toggle write path back
Contract Drop old columns/tables Post-release stability window Restore from backup snapshot
Never run destructive schema drops in the same release as first-write switch unless you have verified backups and rollback drills.
حذف تخریبی schema را همزمان با اولین سوئیچ write اجرا نکنید مگر اینکه بکاپ معتبر و تمرین rollback داشته باشید.

Migration Best Practices بهترین‌رویه‌های Migration
  • Prefer additive changes first; remove columns only after a stable release window.
  • Run backfill in idempotent batches with checkpoints.
  • Gate risky behavior changes behind feature flags when possible.
  • Attach rollback instructions to every production migration PR.
  • ابتدا تغییرات افزودنی را انجام دهید و حذف ستون را به نسخه بعدی موکول کنید.
  • backfill را به‌صورت batch و idempotent با checkpoint اجرا کنید.
  • تغییرات پرریسک را در صورت امکان پشت feature flag قرار دهید.
  • برای هر migration پروداکشن، راهنمای rollback را در PR ثبت کنید.
